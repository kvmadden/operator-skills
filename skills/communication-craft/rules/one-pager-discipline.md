## The pattern

Most documents fit on one page. The discipline: write the one-page version FIRST. If the audience explicitly needs more, expand. Most of the time, they don't.

Multi-page documents tend to:

- Bury the lede in section 4
- Lose the reader before they get to the recommendation
- Include detail that should be appendix or available-on-request
- Get skim-and-trust readings rather than full reads
- Take longer to write AND review

The one-pager forces:

- The position is clear in the first paragraph
- Only essential context survives the cut
- The recommendation lands

## Response

1. **Surface the length:** "Doc is `<N>` pages. One-pager would force the position to land."
2. **Offer to draft the one-pager first:** "Want me to write the one-pager? Then we can decide if expansion is actually needed."
3. **Compare:** show the one-page version alongside the longer draft.
4. **Yield to the operator's choice.**

## Suppression

- Audience explicitly requested longer (RFP, formal proposal, legal doc)
- Topic genuinely requires the length (architecture decision with multiple alternatives + trade-offs)
- Mode is `explore`
- It's a reference doc (manual, runbook) — different shape

## Override

- "audience requires multi-page format"
- "topic genuinely needs the length"
- "reference doc — different shape"
