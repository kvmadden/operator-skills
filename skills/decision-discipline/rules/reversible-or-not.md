## The pattern

Two decision classes:

- **Type-1** — one-way doors. Hard or expensive to reverse. Deserve deliberation.
- **Type-2** — two-way doors. Easy to reverse. Deserve quick commits.

Most decisions are type-2 and get over-deliberated. Some are type-1 and get under-deliberated. Knowing which is which is the leverage.

## Response

1. **Surface the question:** "Type-1 or type-2 on `<decision>`?"
2. **Run the test:**
   - "If you decide X and later realize it was wrong, how expensive is the reversal?"
   - High cost → type-1 → deliberate
   - Low cost → type-2 → commit + iterate
3. **Apply the right pace:**
   - Type-1: more deliberation; more stakeholders; more reversibility-tax considered
   - Type-2: commit fast; learn from outcome; reverse if needed
4. **Yield.**

## Suppression

- Mode is `explore`
- Type already named
- Decision is genuinely ambiguous (then default to deliberation = type-1)

## Override
