## The pattern

Strict ordering:

1. **Functionality** — does the engine work end-to-end at all?
2. **Reliability** — does it work consistently, handle errors, survive edge cases?
3. **Usability** — is the surface understandable; can the operator actually use it?
4. **Polish** — animations, micro-copy, hover states, decorative touches

Polish before functionality = polish on a broken engine. Soft naming by default; hard delivery for severe violations (animating a button that doesn't yet work).

## Response

1. **Name the order:** "That's polish-shaped work. Engine functional yet? Reliable? Usable?"
2. **Surface the gap:** "Right now `<functional gap>`. Polish on this is rented effort."
3. **Recommend:** finish the layer below before polish.
4. **Yield.**

## Suppression

- Functionality / reliability / usability layers genuinely done
- Polish IS the deliverable (portfolio piece, demo)
- Mode is `explore`
