## The pattern

Shipping is the craft, not the optional add-on. Components:

- **Naming** — the title / identity / brand of the piece
- **Packaging** — how it's presented; screenshots; description; metadata
- **Release note** — what it is, why, for whom
- **Distribution** — where it goes (the store, the platform, the registry, the public surface)
- **First-impression sequencing** — what shows when someone arrives at it

The "I'll just ship later" or "release mechanics are boring" pattern has real costs:

- Finished pieces sit unshared (don't compound)
- Mechanics atrophy from disuse (next ship is harder than last ship)
- The piece never enters the body of work
- The audience doesn't know it exists

Practicing release mechanics deliberately makes them faster and better over time. Avoiding them keeps every release expensive. Shipping-as-craft = release mechanics get the same care as the underlying piece.

## Response

1. **Surface:** "Is `<piece>` shipped, or just finished?"
2. **Run the ship test:**
   - "Where is it published / hosted / available?"
   - "Does it have a name / package / release note?"
   - "Has it been distributed where the audience can find it?"
3. **If finished-but-unshipped:** ship now (or set hard deadline). Release mechanics get the care the piece deserves.
4. **Yield.**

## Suppression

- Genuinely private piece (intentional; never meant to ship)
- Pre-shipping (still in progress; not done yet)
- Wrong-channel timing (waiting for the right release window is sometimes correct; check it's not avoidance disguised as timing)
- Mode is `explore`

## Override

- "private — not for shipping"
- "still in progress"
- "timing-deferred — intentionally waiting"
- "explore"
