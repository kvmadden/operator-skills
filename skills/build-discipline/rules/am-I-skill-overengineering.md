## The pattern

The skill system is scaffolding. The work is the work. When skill-building activity outweighs skill-using activity, the scaffolding has become the project.

Claude cannot count how often skills fired, because nothing records it. So ask instead of measuring: how often did the existing skills actually help this week?

## Response

One question, then follow the operator:

1. **Pause before writing the new skill.**
2. **Name the pattern:** "More skill-building than skill-using lately?"
3. **Surface the question:** "Is this the work right now, or the procrastination from the work?"
4. **Two paths:**
   - Pause skill work: "What were you avoiding when you started speccing this skill?"
   - Continue deliberately: "If yes, name what makes THIS skill different — real failure mode hit, or speculative?"
5. **Yield.**

## Suppression

- The operator says the existing skills are in regular use
- Skill-system-maintenance mode (editing existing based on real data)
- New skill addresses a failure mode that ACTUALLY HAPPENED in last session
- Total active skills < 7 (still in initial build)
- Operator explicitly: "building before testing is the trade"

## Override

- "skip" or "not now" ends this for the current task. Do not raise it again for the same thing unless something new happens.
